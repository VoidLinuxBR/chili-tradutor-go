## 1. Обзор

`chili-translator-go` — это оболочка командной строки, написанная на Go, которая автоматизирует перевод файлов разных форматов (скриптов, документации, структурированных данных, man-страниц) на несколько языков одновременно, используя внешние механизмы перевода (через `translate-shell`) и систему кэширования на диске, чтобы избежать повторных повторных переводов.

Программа в первую очередь предназначена для локализации программных проектов: она извлекает переводимые строки из исходного кода через `gettext`/`xgettext`, генерирует `.po`/`.mo` файлы, а также напрямую переводит документы (`.md`, `.txt`, `.json`, `.yaml`, `.html`, man-страницы), минуя поток gettext.

## 2. Цели

- Автоматически переводите один или несколько файлов в настраиваемый список языков.
- Минимизируйте сетевые вызовы за счет повторного использования уже выполненных переводов (постоянный кеш).
- Поддерживает как классический поток gettext (`.po`/`.mo`, для использования в приложениях `i18n`), так и прямой перевод документов и данных.
- Параллельная обработка нескольких языков с визуальным отображением прогресса на терминале в режиме реального времени.
- Автоматическое определение типа файла (по расширению или shebang) без необходимости ручной настройки.

## 3. Функциональный объем

### 3.1 Поддерживаемые форматы ввода

| Расширение/критерий | Тип обнаружен | Поток перевода |
|---|---|---|
| расширенное расширение, com shebang (`#!/usr/bin/env python` и т. д.) | скрипт (python, php, perl, рубин, javascript, оболочка) | gettext(`.pot`/`.po`/`.mo`) |
| нет расширения, нет ерунды | простой текст | получить текст |
| от `.1` до `.9` | справочная страница | построчный перевод с защитой макросов roff |
| `.sh .py .php .c .cpp .go .pl .rb` | исходный код | gettext(`.pot`/`.po`/`.mo`) |
| `.html .htm` | HTML | построчный перевод с защитой тегов |
| `.md .markdown` | Уценка | построчный перевод с защитой кодовых блоков, с сохранением префиксов (`#`, `-`, `1.`) |
| `.txt` | простой текст | построчный перевод |
| `.json` | JSON | рекурсивный перевод строковых значений в карты |
| `.yaml .yml` | ЯМЛ | рекурсивный перевод (через парсер JSON) |
| `.пот` | шаблон gettext | копируется в `pot/` и обрабатывается как PO |
| любое другое расширение | запасной вариант | рассматривается как оболочка/gettext |

### 3.2 Поток выполнения (для каждого файла)

1. Проверяет, существует ли файл.
2. Обнаруживает тип (`detectFileType`) и подготавливает соответствующий выходной каталог (`pot/`, `doc/`, `txt/`, `json/`, `yml/`, `html/`, ``man/`).
3. Для потока gettext: запускает `xgettext` для извлечения строк и генерирует стандартизированный заголовок POT (`stampPotHeader`).
4. Проверяет, есть ли реальный контент для перевода (`hasActualContent`); если их нет, он очищает пустые артефакты и прерывает работу с файлом с предупреждением.
5. Запускает одну горутину для каждого целевого языка, ограниченную семафором размера "jobs" (`-j`, по умолчанию 8).
6. Каждая горутина вызывает подпрограмму перевода, специфичную для формата (translateManPage, translateHTML, translateMarkdown, translatePlaintext, translateJSON или трио prepareMsginit/translateFile/writeMsgfmtToMo для потока gettext).
7. Каждая строка/строка/msgid передается через callUniversalTranslator, который:
   - нормализует и запрашивает локальный кеш перед любыми сетевыми вызовами;
   - защищает переменные, форматирует заполнители, ссылки и URL-адреса перед отправкой в систему перевода (`protectVariables`/`restoreVariables`);
   - вызвать `trans` (translate-shell) с максимум 3 попытками и постепенной отсрочкой;
   - записывает результат в кеш (`~/.cache/chili-tradutor-go/cache.json`).
8. Прогресс отображается в реальном времени по языкам с использованием escape-кодов ANSI для перемещения курсора в многострочной области терминала.
9. В конце каждого файла отображается краткая статистика (время, попадания в кеш, сетевые вызовы).
10. В конце всех файлов (если их несколько) отображается общее резюме.

### 3.3 Система кэширования

- Локально: `$HOME/.cache/chili-tradutor-go/cache.json`.
- Структура: `map[язык]map[textoNormalizado]CacheEntry{Value, LastUsed}`.
- Загружается один раз в начале (`loadCache`) и сохраняется один раз в конце обычного выполнения (`saveCache`, через `defer`).
- `--force` игнорирует существующие записи кэша и принудительно выполняет повторную трансляцию.
- `--clean-cache` удаляет записи, которые не использовались более 30 дней.

### 3.4 Защита непереводимого контента

Функция ProtectVariables заменяет заполнители (CHILI_REF_N_CHILI) перед отправкой текста в систему перевода, а затем восстанавливает его (restoreVariables):
- Варианты оболочки: `$VAR`, `${VAR}`.
- Простые спецификаторы форматирования: `%s`, `%d` (только строчные буквы).
- Ссылки и изображения Markdown: `[texto](url)`, `![alt](url)`.
- URL-адреса (`http://`, `https://`).

Определенные форматы добавляют собственную защиту перед делегированием функции callUniversalTranslator:
- **Страницы руководства:** макросы roff (строки, начинающиеся с `.`) содержат только текст после переведенного макроса; комментарии (`\"`) сохраняются без изменений.
- **HTML:** теги (`<...>`) заменяются заполнителями (`CHILI_HTML_N_CHILI`) перед переводом строки.
- **Markdown:** блоки, разделенные ``` ``` ```, не переводятся; Префиксы названия/списка/нумерации сохраняются вне перевода.

### 3.5 Самотестирование («--self-test»)

Запускает упрощенный набор внутренних проверок (зависимости, круговой обход `protectVariables`/`restoreVariables`) и печатает на терминал отчет OK/FAIL.

### 3.6 Режим `--self`

Специализированный режим для извлечения и перевода собственных строк из двоичного файла `chili-translator-go` (использует ключевые слова для извлечения `T`/`TN` из самого исходного кода через `xgettext`).

## 4. Интерфейс командной строки

```
chili-tradutor-go -i <arquivo> [opções]
```

| Короткий флаг | Длинный флаг | Описание | Стандарт |
|---|---|---|---|
| `-я` | `--inputfile` | Исходный файл(ы) (принимает кратные значения, в том числе через позиционные аргументы) | — |
| `-л` | `--язык` | Список идиом-alvo (например: `pt_BR,en`) или `all` | `pt_BR,en,es,it,de,fr,ru,zh_CN,zh_TW,ja,ko` |
| `-е` | `--двигатель` | Система перевода: `google`, `bing`, `yandex` | `гугл` |
| `-j` | `--работы` | Количество синхронных переводов (параллелизм на язык) | `8` |
| `-с` | `--источник` | Исходный язык | `авто` |
| `-ф` | `--force` | Игнорировать кеш, принудительно выполнить новый перевод | `ложь` |
| — | `--сам` | Специализированное извлечение самого двоичного файла | `ложь` |
| — | `--самопроверка` | Выполняет самопроверку целостности | `ложь` |
| — | `--clean-cache` | Удалить записи кэша, не используемые в течение 30 дней | `ложь` |
| `-q` | `--тихо` | Тихий режим (частичный — см. ограничения) | `ложь` |
| `-v` | `--verbose` | Подробный режим (в настоящее время не реализован) | `ложь` |
| `-V` | `--версия` | Показывает версию программы | — |

Поддерживаемые языки в `--other Language`: `ar bg cs da de el en es et fa fi fr he hi hr hu is it ja ko nl no pl pt_PT pt_BR ro ru sk sv tr uk zh_CN zh_TW`.

## 5. Внешние зависимости

| Двоичный | Пакет | Использование |
|---|---|---|
| `xgettext` | получить текст | извлечение строк из исходного кода |
| `мсгинит` | получить текст | Инициализация файла `.po` по языку |
| `msgfmt` | получить текст | компиляция `.po` → `.mo` |
| `gettext` / `ngettext` | получить текст | перевод самого интерфейса программы (`T`/`TN`) |
| `транс` | перевести-оболочка | выполнение перевода через внешний движок |

Программа проверяет наличие этих двоичных файлов при запуске («checkDependities») и предлагает автоматическую установку через обнаруженный менеджер пакетов («pacman», «xbps-install», «apt», «dnf») в соответствии с дистрибутивом, указанным в «/etc/os-release».

Также проверяет подключение к Интернету в начале выполнения (`checkInternet`, проверка TCP на `8.8.8.8:53`); в автономном режиме кеш по-прежнему обращается к нему, но некэшированный текст возвращается непереведенным.

## 7. Выходной терминал

- Заголовок с именем/версией, обнаруженным типом файла, движком, исходным языком, количеством заданий и путем к кэшу.
- Исходный список целевых языков со статусом «[Ожидание...]».
- Индикатор выполнения по языку, обновляемый на месте с помощью escape-кодов ANSI (`\033[nA`, `\033[K`, `\033[nB`), показывающий язык, процентную шкалу и суффикс формата (`MD`, `TXT`, `HTML`, `MAN`, `PO`, `JSON`, `OK`).
- Краткая статистика по файлам: затраченное время, попадания в кеш (%), сетевые вызовы (%), общее количество.
- Итоговое резюме (только если обработано более одного файла): общее время, попадания в кэш, сетевые вызовы, сбои (если таковые имеются).
- Использование цвета через `github.com/fatih/color`: голубой (выделение), зеленый (успех), желтый (предупреждение/статус), красный (ошибка), синий (вторичная информация).

## 8. Конкуренция

- Канал `sync.WaitGroup` + семафор (`chan struct{}, jobs`) ограничивает количество языков, которые одновременно переводятся в одном файле.
- `sync.Mutex` (`mu`) защищает доступ к карте общего кэша.
- `sync.Mutex` (`muConsole`) сериализует запись в терминал между горутинами.
- Счетчик завершения языка (`langsDone`) использует `sync/atomic`.

## 9. Известные ограничения (v2.1.20)

- Файлы `.yaml`/`.yml` десериализуются с помощью `encoding/json` и работают только для YAML, совместимого с синтаксисом JSON.
- `translateMap` не обрабатывает массивы (`[]interface{}`), а только карты.
- Блоки `<script>`/`<style>` в HTML и встроенные фрагменты кода (`` `code` ``) в Markdown не защищены от перевода.
- Флаг --verbose присутствует в CLI, но не влияет на текущее поведение.
- `--quiet` подавляет только индикаторы выполнения, но не другие сообщения заголовка/сводки.
- Нет поддержки других систем перевода, кроме тех, которые поддерживаются `translate-shell` (`google`, `bing`, `yandex`).
- Нет обработки сигналов (SIGINT/SIGTERM) для очистки кэша при ручном прерывании.

## 10. Требования к окружающей среде

- Go 1.x (сборка), система Linux (использование `/etc/os-release`, `LC_ALL=C` для изоляции локали в подпроцессах).
- Доступ в Интернет для перевода (оффлайн-режим работает только с предварительно заполненным кешем).
- Разрешение на запись в `$HOME/.cache/chili-tradutor-go/` и текущий рабочий каталог (для `pot/`, `doc/`, `txt/`, `json/`, `yml/`, `html/`, `man/`, `usr/`).
